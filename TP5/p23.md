## Análisis del programa

El código define **tres funciones con el mismo nombre** `f1`, simulando sobrecarga:

```python
def f1():          return 5
def f1(x):         return x*2
def f1(x, y="default"):
    if y == "default": return 10*x
    else:              return x*((-1)*y)
```

Sin embargo, en Python **cada definición sobreescribe a la anterior**, por lo que al final solo existe `f1(x, y="default")`.

---

## a. ¿Por qué genera error?

Al evaluar `f1() + f1(1) + f1('a') + f1(1, 0) + f1('a', 3)`, Python solo conoce la **última definición** de `f1`. Los errores son:

| Llamada | Problema |
|---|---|
| `f1()` | `TypeError`: faltan argumentos obligatorios (`x` es requerido) |
| `f1(1)` | ✓ Retorna `10*1 = 10` |
| `f1('a')` | ✓ Retorna `10*'a' = 'aaaaaaaaaa'` |
| `f1(1, 0)` | ✓ Retorna `1*((-1)*0) = 0` |
| `f1('a', 3)` | `TypeError`: `'a' * ((-1)*3)` → `'a' * -3` → error de tipo |

### Características del sistema de tipos responsables:

1. **Ausencia de sobrecarga de funciones (*overloading*):** Python no distingue funciones por aridad ni por tipo de parámetros. El nombre `f1` es simplemente una variable que apunta a un único objeto función; cada `def` reemplaza al anterior.

2. **Tipado dinámico con verificación en tiempo de ejecución:** Los tipos no se comprueban hasta que la operación se ejecuta. El error en `'a' * -3` no se detecta en compilación sino al momento de evaluar.

3. **Tipado fuerte (*strong typing*):** Python **no coerciona** silenciosamente los operandos. No intenta convertir `'a'` o `-3` para que la multiplicación tenga sentido; simplemente lanza `TypeError`.
