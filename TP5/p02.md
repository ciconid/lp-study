## Pregunta 2
> Defina qué significa que un lenguaje sea fuertemente tipado. ¿Qué desventajas tiene un lenguaje que no es fuertemente tipado? Ejemplifique.

---

## Respuesta

### Lenguaje fuertemente tipado (*strongly typed language*)

Un lenguaje es **fuertemente tipado** si garantiza la propiedad conocida como *type safety*: el lenguaje debe ser capaz de **detectar todos los errores de tipos**, independientemente de en qué momento lo haga (compilación o ejecución).

> *"Esta propiedad garantiza lo que se conoce como type safety. Para que un lenguaje satisfaga esta propiedad debe detectar todos los errores de tipos. Si el lenguaje maneja muy bien los tipos, pero hay un detalle que no es capaz de detectar entonces el lenguaje pierde la propiedad, el lenguaje es o no es fuertemente tipado, no hay grises aquí."*
> — 06-SistemaDeTipos.pdf (p. 2)

> *"A programming language is strongly typed if type errors are always detected. This requires that the types of all operands can be determined, either at compile time or at run time."*
> — Concepts of Programming Languages – Sebesta, E12 (p. 482)

#### Aspectos clave de la definición

1. **No es binario en cuanto al momento**: un lenguaje fuertemente tipado puede hacer los controles estáticamente (en compilación) o dinámicamente (en ejecución). Lo que importa es que **todos** los errores de tipo sean detectados, sin excepción.

   > *"Un detalle importante a tener en cuenta es que no importa en qué momento detecte el error de tipos, lo importante es que lo detecte y permita al programador poder hacer algo con ese error para que la aplicación que está desarrollando no colapse por un error de tipos."*
   > — 06-SistemaDeTipos.pdf (p. 2)

2. **Es una propiedad binaria** (el lenguaje la tiene o no): si existe aunque sea un caso de error de tipo que el lenguaje no puede detectar, el lenguaje **no** es fuertemente tipado.

3. **Diferencia con dureza del tipado**: la dureza (*strong typing*) es un *grado* que mide qué tan restrictivo es el sistema de tipos en cada característica; la propiedad de fuertemente tipado es binaria. Un lenguaje puede tener alta dureza en varios aspectos y aún así no ser fuertemente tipado si hay algún caso no controlable.

   > *"La dureza del tipado no es una propiedad de los lenguajes, sino que es un grado que surge como consecuencia de las restricciones que impone el sistema de tipos [...]. Noten que es importante distinguir esta noción de la propiedad de fuertemente tipado."*
   > — 06-SistemaDeTipos.pdf (p. 2)

---

### Desventajas de un lenguaje que **no** es fuertemente tipado

Un lenguaje que no detecta todos los errores de tipos expone al programador y a los usuarios finales a los siguientes problemas:

#### 1. Errores silenciosos en tiempo de ejecución
Si un error de tipo no es detectado, el programa puede continuar ejecutándose con datos incorrectos, produciendo resultados erróneos sin ningún aviso. El error puede manifestarse mucho más tarde y en un lugar diferente del código, dificultando el diagnóstico.

#### 2. Comportamiento indefinido o impredecible
En lenguajes como C y C++, operar sobre un `union` con el tipo incorrecto produce **comportamiento indefinido**, ya que el lenguaje no verifica qué campo del `union` está activo en cada momento.

> *"Unions are potentially unsafe constructs in some languages. They are one of the reasons why C and C++ are not strongly typed: These languages do not allow type checking of references to their unions."*
> — Concepts of Programming Languages – Sebesta, E12 (p. 457)

#### 3. Coerciones implícitas que ocultan errores
Las reglas de coerción de un lenguaje también afectan directamente la propiedad. Si el lenguaje aplica coerciones implícitas en contextos ambiguos, un error de tipos puede pasar desapercibido porque el lenguaje "resuelve" la incompatibilidad automáticamente, aunque el resultado no sea el esperado por el programador.

> *"The coercion rules of a language have an important effect on the value of type checking."*
> — Concepts of Programming Languages – Sebesta, E12 (p. 482)

#### 4. Reducción de confiabilidad

> *"The importance of strong typing lies in its ability to detect all misuses of variables that result in type errors."*
> — Concepts of Programming Languages – Sebesta, E12 (p. 482)

Si el lenguaje no es fuertemente tipado, la confiabilidad del software disminuye: los errores de tipo que podrían haberse detectado tempranamente se convierten en bugs de producción, más costosos de depurar y corregir.

### Ejemplos

#### C — `union` sin chequeo de tipos

```c
#include <stdio.h>

union Mixto {
    int entero;
    float real;
};

int main() {
    union Mixto m;
    m.real = 3.14f;
    // Se lee el campo incorrecto; comportamiento indefinido
    printf("%d\n", m.entero);  // imprime basura
    return 0;
}
```

C no verifica qué campo del `union` fue el último en ser asignado, por lo que leer `m.entero` después de asignar `m.real` produce comportamiento indefinido. Este error de tipo no es detectado ni en compilación ni en ejecución.

#### JavaScript — coerciones implícitas que silencian errores de tipo

```javascript
console.log("5" - 2);   // 3  (string convertido a número implícitamente)
console.log("5" + 2);   // "52" (número convertido a string implícitamente)
console.log(null + 1);  // 1  (null coercionado a 0)
console.log([] + {});   // "[object Object]"
```

JavaScript aplica coerciones implícitas extensas. Ninguno de estos usos genera un error de tipo; el programador puede escribir código con errores semánticos graves que el lenguaje silenciosamente "acepta".

#### Python — lenguaje fuertemente tipado (contraejemplo positivo)

```python
>>> "5" + 2
TypeError: can only concatenate str (not "int") to str
```

Python detecta el error de tipo y lanza una excepción. Aunque el chequeo es dinámico (en ejecución), el error no pasa desapercibido, lo que lo hace fuertemente tipado.
