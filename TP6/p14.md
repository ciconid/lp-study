El mecanismo de **pass-by-object-reference** (también llamado *pass-by-assignment*) en Python es uno de los conceptos más importantes y, a la vez, más malentendidos del lenguaje. Aquí va una explicación completa con un widget interactivo para verlo en acción.

* * * * *

### La idea central: variables como etiquetas

En Python, las variables no "contienen" valores --- son **etiquetas** que apuntan a objetos en memoria. Cuando pasás un argumento a una función, lo que se copia es la etiqueta (la referencia), no el objeto en sí.

Esto tiene una consecuencia clave que divide los casos en dos:

-   **Objetos mutables** (listas, diccionarios, conjuntos): la función puede modificar el objeto original a través de su referencia.
-   **Objetos inmutables** (enteros, strings, tuplas): la función no puede modificar el original. Si reasigna la variable, solo mueve la etiqueta local.

* * * * *

### Los tres casos que hay que entender

**Caso 1 --- Inmutables:** `x = 10` dentro de la función crea una nueva etiqueta local. El `x` externo no se toca.

**Caso 2 --- Mutables (mutación):** `lista.append(4)` modifica el mismo objeto en memoria. El caller ve el cambio.

**Caso 3 --- Mutables (reasignación):** `lista = [99, 100]` solo redirige la etiqueta local a un objeto nuevo. El original no cambia.

## Regla práctica para no confundirse

La pregunta clave siempre es: **¿la función muta el objeto o reasigna la variable?**

-   `lista.append(x)`, `lista[0] = x`, `dict["k"] = v` → **muta** → el caller ve el cambio.
-   `lista = nueva_lista` → **reasigna** → solo afecta la etiqueta local.

### Cómo "simular" pass-by-value o pass-by-reference clásico

Si querés que la función **no modifique** una lista que pasás, pasá una copia:

python

```
agregar(mi_lista[:])     # copia superficial
agregar(list(mi_lista))  # equivalente
import copy; agregar(copy.deepcopy(mi_lista))  # copia profunda (anidados)
```

Si querés que la función pueda **cambiar** un valor inmutable y que el caller lo vea, devolvé el valor:

python

```
def incrementar(x):
    return x + 1

n = incrementar(n)   # n ahora vale 11
```

### ¿Por qué Python lo hace así?

Este diseño es intencional: Python evita copias costosas de objetos grandes al pasar argumentos. En vez de duplicar una lista de millones de elementos, simplemente pasa la referencia. La responsabilidad de no mutar algo que no debería mutarse recae en el programador (o en hacer la copia explícita).

# Análisis por criterios

## Python vs Java: pasaje de parámetros

Ambos lenguajes usan el mismo mecanismo conceptual — pasan referencias por valor. La diferencia real está en que Java tiene primitivos (`int`, `double`, etc.) que viven en el stack y se copian por valor puro, mientras que en Python todo es un objeto en el heap.

---

## Comparación por criterios de la cátedra

### 1. Writability (facilidad de escritura)

Python es más simple de escribir: una sola regla aplica a todo ("se pasa la referencia al objeto"), sin distinción de tipos. No hay que declarar tipos en la firma ni recordar cuáles son primitivos.

Java requiere que el programador conozca la distinción primitivo/objeto al escribir funciones, y que use explícitamente `Collections.unmodifiableList()`, copias defensivas, o `final` cuando quiere proteger un argumento. Más ceremonia para expresar la misma intención.

**Ventaja: Python**

---

### 2. Readability (facilidad de lectura)

En Java, la firma del método comunica directamente si un argumento puede ser modificado: `int` nunca cambia, `ArrayList` podría cambiar. El lector tiene una señal visual clara sin leer el cuerpo.

En Python, la firma no da esa información. Para saber si `modificar(x)` altera el argumento original hay que conocer si el tipo de `x` es mutable, y además leer el cuerpo para ver si muta o reasigna.

**Ventaja: Java**

---

### 3. Reliability (confiabilidad / menos errores)

Java detecta en compilación errores relacionados con parámetros `final` reasignados, y la distinción de tipos reduce efectos secundarios inesperados. El sistema de tipos actúa como una red de seguridad.

Python no tiene esa red: un error conceptual (mutar algo que no debería mutarse) se descubre en ejecución o en revisión de código. El comportamiento diferente entre mutables e inmutables es una fuente frecuente de bugs en programadores que aprenden el lenguaje.

**Ventaja: Java**

---

### 4. Cost / Efficiency (costo y eficiencia)

Ambos lenguajes evitan copiar objetos grandes al pasar argumentos — solo se copia la referencia. En ese sentido son equivalentes para objetos.

La diferencia está en los primitivos: Java almacena `int`, `double`, etc. directamente en el stack, lo que es más eficiente en tiempo y memoria que Python, donde hasta un `int` es un objeto en el heap con overhead de cabecera de objeto, conteo de referencias y gestión de garbage collector.

**Ventaja: Java** (especialmente en código numérico intensivo)

---

## Resumen

| Criterio      | Python | Java |
|---------------|--------|------|
| Writability   | ✓ Una sola regla, sin declaraciones | Más ceremonia para proteger argumentos |
| Readability   | La firma no informa mutabilidad | La firma distingue primitivo/objeto |
|

## Conclusión

El resultado observable para el programador es prácticamente idéntico en los tres casos del ejercicio. La diferencia real es de diseño del lenguaje: Java separa primitivos de objetos dando garantías estáticas más fuertes; Python trata todo uniformemente pero exige que el programador conozca la mutabilidad de cada tipo. Ninguno es mejor en términos absolutos — Java prioriza seguridad explícita, Python prioriza uniformidad y simplicidad conceptual.
