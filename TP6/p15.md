## Pasaje por referencia en Pascal sin aliasing

### Concepto previo: aliasing

El **aliasing** ocurre cuando dos o más nombres (variables) referencian la misma
posición de memoria simultáneamente. En pasaje por referencia esto es la norma:
el parámetro formal y el argumento real apuntan al mismo lugar.

```pascal
procedure incrementar(var x: integer);
begin
  x := x + 1;
end;

var n: integer;
begin
  n := 5;
  incrementar(n);  { x y n son alias: misma dirección }
end.
```

Aquí `x` y `n` son aliases — modificar `x` modifica `n`.

---

### ¿Cuándo el pasaje por referencia NO produce aliasing?

Pascal permite pasar por referencia (`var`) expresiones que designan una
**componente específica** de una estructura. En ese caso, el parámetro formal
recibe la dirección de esa componente, pero **ninguna otra variable del programa
tiene un nombre que refiera exactamente a esa misma celda**.

---

### Caso 1: elemento de un array sin variable intermedia

```pascal
procedure duplicar(var x: integer);
begin
  x := x * 2;
end;

var v: array[1..5] of integer;
begin
  v[1] := 10;
  v[2] := 20;
  duplicar(v[3]);  { se pasa la dirección de v[3] }
end.
```

`x` apunta a la celda de `v[3]`. No existe ninguna variable declarada con el
nombre `v[3]` — es una posición anónima dentro del array. Mientras `duplicar`
se ejecuta, **ningún otro nombre en el programa designa exactamente esa celda**,
por lo que no hay aliasing.

Si en cambio se hiciera:

```pascal
{ Esto SÍ produce aliasing }
duplicar(v[i]);   { y dentro del procedimiento se modifica i }
```

...podría haber aliasing indirecto si el índice `i` es una variable global
accesible desde el procedimiento.

---

### Caso 2: campo de un registro

```pascal
type
  Punto = record
    x: real;
    y: real;
  end;

procedure escalar(var componente: real; factor: real);
begin
  componente := componente * factor;
end;

var p: Punto;
begin
  p.x := 3.0;
  p.y := 4.0;
  escalar(p.x, 2.0);  { se pasa la dirección del campo x de p }
end.
```

El parámetro `componente` apunta al campo `p.x`. El campo `p.y` está en una
dirección distinta y no es afectado. No hay otro nombre que refiera a `p.x`
concurrentemente, así que no hay aliasing.

---



### Resumen

| Situación                                                        | ¿Aliasing? |
|------------------------------------------------------------------|------------|
| `var n` pasando variable simple única                            | **Sí**     |
| `var v[3]` — índice literal, celda fija                          | No         |
| `var v[i]` con `i` global accesible desde el procedimiento       | **Sí**     |
| `var v[i]` con `i` local e inaccesible desde el procedimiento    | No         |
| `var p.campo` de un registro                                     | No         |
| `var a` y `var b` con argumentos distintos                       | **Sí** (formal con su real, pero no entre sí) |
| `proc(x, x)` — mismo argumento dos veces                         | **Sí**     |
| Parámetro `var` + variable global del mismo nombre               | **Sí**     |

El pasaje por referencia en Pascal **no produce aliasing siempre que el
argumento real designe una celda de memoria a la que no se puede acceder por
ningún otro nombre activo durante la ejecución del procedimiento**.
