# ¿Es JavaScript un lenguaje fuertemente tipado?

No, JavaScript no es un lenguaje **fuertemente tipado** según la definición de la cátedra.

## Justificación

Para que un lenguaje sea fuertemente tipado, debe garantizar la detección de todos los errores de tipos, asegurando que el programador sea informado cuando ocurre una operación inválida.

En el ejercicio anterior se demostró que JavaScript prioriza la flexibilidad y la continuidad de la ejecución sobre la seguridad de tipos.

### Caso 1: `"hola" * 4`

Al evaluar:

```javascript
"hola" * 4
```

el sistema no detecta un error de tipo (operar una cadena con un número), sino que aplica una coerción implícita y devuelve:

```javascript
NaN
```

### Caso 2: `"hola".longitud`

Al evaluar:

```javascript
"hola".longitud
```

el lenguaje devuelve:

```javascript
undefined
```

ante una propiedad inexistente, en lugar de lanzar una excepción por acceso ilegal.

### Consecuencia

Debido a que el lenguaje utiliza un sistema de coerciones agresivas diseñado para que los operandos muten y la ejecución no se detenga, muchos errores de tipos pasan inadvertidos, lo que invalida la propiedad de tipado fuerte.

## Cambios para endurecer el sistema de tipos

Para aumentar la dureza del sistema de tipos de JavaScript, se podrían realizar los siguientes cambios.

### Eliminar las coerciones implícitas en expresiones mixtas

Se debería prohibir que el lenguaje realice transformaciones automáticas de tipos cuando los operandos no coinciden con lo esperado por el operador.

Un sistema más duro obligaría al programador a realizar conversiones explícitas (*casting*) y lanzaría un error de tipos inmediato si se intenta, por ejemplo, sumar un número con una cadena sin una instrucción previa de transformación.

### Implementar chequeo de tipos obligatorio en parámetros y acceso a miembros

El lenguaje debería lanzar un error de tipos si un subprograma recibe un argumento cuyo tipo no es el esperado, en lugar de permitir la ejecución con datos incompatibles.

Asimismo, el acceso a propiedades inexistentes (como `.longitud`) debería resultar en un error de ejecución que detenga el flujo, garantizando que el programador identifique el fallo en la lógica de tipos.

JavaScript no puede considerarse fuertemente tipado bajo la definición de la cátedra debido a que utiliza coerciones implícitas y mecanismos de tolerancia a errores que permiten que ciertas inconsistencias de tipos pasen inadvertidas.

Un sistema más estricto requeriría eliminar dichas coerciones automáticas y reportar explícitamente cualquier uso incompatible de tipos.
