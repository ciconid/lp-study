### Respuesta directa

Python usa **ambiente del punto de definición** de la función (scope léxico / estático), no el del llamador ni el del llamado. Cuando una función necesita resolver una variable no local, sube por la cadena de scopes **donde fue escrita**, ignorando completamente desde dónde fue llamada.

* * * * *

### Experimento para demostrarlo

El diseño del experimento es simple: crear una variable con el **mismo nombre** en dos ambientes distintos --- el de definición y el del llamador --- y observar cuál usa la función.

python

```
x = "global (definición)"

def mostrar():
    print(x)   # x no es local → busca en el scope donde fue definida

def llamador():
    x = "local del llamador"   # mismo nombre, distinto scope
    mostrar()                  # ¿qué x ve mostrar()?

llamador()
```

**Salida:**

```
global (definición)
```

`mostrar()` imprime el `x` global --- el del scope donde fue **escrita** --- aunque fue llamada desde `llamador()`, que tiene su propio `x` con un valor diferente. El ambiente del llamador es completamente ignorado.

* * * * *

### Segunda variante: función pasada como parámetro

Este caso es más revelador porque la función viaja a un contexto completamente distinto:

python

```
x = "scope de definición"

def mostrar():
    print(x)

def ejecutar(func):
    x = "scope del llamado (callee)"   # variable local de ejecutar
    func()                              # ¿qué x ve func?

ejecutar(mostrar)
```

**Salida:**

```
scope de definición
```

Aunque `mostrar` se ejecuta **dentro** de `ejecutar`, y `ejecutar` tiene su propio `x`, la función sigue viendo el `x` de donde fue definida. El scope del callee tampoco influye.

* * * * *

### Conclusión

Python implementa **scope léxico estático**: el ambiente de referenciamiento de una función queda fijado en el momento de su **definición**, no de su llamada. Esto es equivalente al mecanismo de closure que vimos en JavaScript --- de hecho, es el mismo principio. La regla que aplica Python para resolver nombres es la conocida como **LEGB**:

-   **L**ocal --- variables definidas en la propia función.
-   **E**nclosing --- scopes de funciones que la contienen léxicamente.
-   **G**lobal --- el módulo.
-   **B**uilt-in --- nombres predefinidos de Python.

En ningún punto de esa cadena aparece el scope del llamador.
