# Formas de pasaje de parámetros

Las formas de pasaje de parámetros son los mecanismos que permiten la comunicación de una unidad (subprograma) con el resto del programa, facilitando una computación parametrizada y más confiable que el acceso a variables no locales.

Según las fuentes, los métodos de pasaje se pueden clasificar de acuerdo con su modelo semántico y el momento en que se evalúan los parámetros actuales.

## Modos semánticos básicos

### Modo in
El parámetro formal recibe datos del parámetro actual.

### Modo out
El parámetro formal transmite datos al parámetro actual al finalizar la ejecución.

### Modo inout
El parámetro realiza ambas funciones, recibiendo y transmitiendo información.

## Modelos de implementación por copia (Evaluación ansiosa)

### Por valor (Modo in)
El parámetro formal se inicializa con el valor del actual en el momento de la llamada y funciona internamente como una variable local; los cambios realizados dentro no afectan al llamador.

### Por resultado (Modo out)
No se transmite valor inicial; al terminar la ejecución, el valor final del parámetro formal se copia de regreso a la variable del llamador.

### Por valor-resultado (Modo inout)
Es una combinación de los dos anteriores; el formal se inicializa con el valor actual y su valor final se vuelve a copiar al parámetro actual al concluir la unidad.

## Modelos por camino de acceso (Evaluación ansiosa)

### Por referencia (Modo inout)
Se transmite la dirección de memoria o camino de acceso del parámetro actual, permitiendo que la unidad llamada comparta y modifique directamente la variable original.

## Modelos de evaluación tardía

### Por nombre
Vinculado a la evaluación de orden normal, el parámetro actual se evalúa cada vez que se hace referencia al formal dentro del cuerpo del subprograma mediante un procedimiento intermedio llamado *thunk*.

### Por necesidad
Vinculado a la evaluación perezosa, el parámetro se evalúa solo la primera vez que se usa y el resultado se almacena para usos posteriores, evitando recálculos innecesarios.

# Implementación en lenguajes específicos

## Java

Java implementa estrictamente el pasaje por valor para todos sus parámetros.

- En el caso de tipos primitivos (escalares), el valor original es inmutable para el método invocado.
- Para los objetos, lo que se pasa por valor es la variable de referencia (la dirección), lo que permite modificar el estado interno del objeto, pero no cambiar la referencia original para que apunte a un objeto distinto.

## Go

Al igual que Java, el pasaje de parámetros en Go es siempre por valor.

- Para tipos básicos, arreglos y estructuras, el sistema crea una copia física completa de los datos.
- Para tipos como *slices*, *maps* o *channels*, se copia un descriptor que contiene punteros a los datos, permitiendo que la función llamada modifique la información compartida en memoria.

## C#

C# ofrece mayor flexibilidad:

- Utiliza pasaje por valor de forma predeterminada.
- Permite pasaje por referencia explícito mediante la palabra reservada `ref`.
- Permite parámetros de modo `out` mediante el modificador `out`.
