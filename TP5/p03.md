## Pregunta 3
> ¿Cuál es la diferencia entre un error del lenguaje y un error de aplicación? ¿Qué relación tienen estos conceptos con la noción de lenguaje fuertemente tipado?

---

## Respuesta

### Error del lenguaje

Un **error del lenguaje** es una violación a una regla definida explícitamente en el sistema de tipos o en la semántica del lenguaje. Son errores que el lenguaje *puede* (y en un sistema fuertemente tipado, *debe*) detectar, ya sea en compilación o en ejecución.

Estos errores ocurren cuando un programa intenta realizar una operación que el sistema de tipos prohíbe: pasar un argumento del tipo incorrecto, aplicar un operador sobre tipos incompatibles, acceder a un campo de un registro variante con el tipo equivocado, etc.

> *"El tipo y tiempo de chequeo: el chequeo de tipo consiste en verificar que el tipo de una entidad corresponda al esperado por el contexto."*
> — 06-SistemaDeTipos.pdf (p. 1)

> *"The importance of strong typing lies in its ability to detect all misuses of variables that result in type errors."*
> — Concepts of Programming Languages – Sebesta, E12 (p. 482)

**Ejemplo** (error del lenguaje en Python):
```python
>>> "hola" + 5
TypeError: can only concatenate str (not "int") to str
```
El lenguaje detecta el error porque la operación `+` entre `str` e `int` viola una regla del sistema de tipos.

---

### Error de aplicación

Un **error de aplicación** es un error lógico que es incorrecto desde el punto de vista del dominio del problema, pero que **no viola ninguna regla del sistema de tipos**. El lenguaje no lo puede detectar porque, desde su perspectiva, los tipos son compatibles.

Estos errores surgen cuando el sistema de tipos no tiene suficiente granularidad para distinguir entre conceptos del dominio que comparten el mismo tipo. El programador confunde dos entidades del dominio, pero el tipo subyacente de ambas es el mismo, por lo que el lenguaje no puede intervenir.

> *"Un tipo de dato define una colección de valores y un conjunto predefinido de operaciones para esos valores."*
> — 05-Tipos.pdf (p. 1)

La consecuencia directa de esto es que los tipos básicos (como `float`, `int`) son "ciego" al dominio: no distinguen entre una temperatura y un peso si ambos se representan como `float`.

**Ejemplo** (error de aplicación):
```python
temperatura_celsius: float = 36.6
peso_kg: float = 70.0

# Operación sin sentido semántico, pero correcta para el sistema de tipos
resultado = temperatura_celsius + peso_kg  # no da error; el lenguaje no puede saberlo
```

La suma es un error lógico de la aplicación (sumar temperatura y peso es absurdo), pero el lenguaje no puede detectarlo porque ambas variables son `float` y la suma de dos `float` es una operación perfectamente válida.

---

### Relación con la propiedad de lenguaje fuertemente tipado

La propiedad de **fuertemente tipado** se define exclusivamente en términos de **errores del lenguaje**: un lenguaje es fuertemente tipado si y solo si detecta *todos* los errores de tipo (errores del lenguaje).

> *"Para que un lenguaje satisfaga esta propiedad debe detectar todos los errores de tipos."*
> — 06-SistemaDeTipos.pdf (p. 2)

La propiedad **no aplica** a los errores de aplicación: ningún sistema de tipos convencional puede detectarlos porque no representan una violación de regla del lenguaje. Esto significa que:

- Un lenguaje fuertemente tipado **garantiza** la ausencia de errores del lenguaje no detectados.
- Los **errores de aplicación** quedan siempre bajo la responsabilidad del programador, independientemente de cuán fuerte sea el sistema de tipos.

En otras palabras, la propiedad de fuertemente tipado es una condición necesaria pero no suficiente para tener programas correctos.

---

### Estrategia para convertir errores de aplicación en errores del lenguaje

Una técnica para reducir los errores de aplicación es **definir tipos distintos para conceptos distintos del dominio**, usando tipos de datos abstractos o tipos nominales. De esta manera, lo que antes era un error invisible para el lenguaje se convierte en un error detectable.

> *"El universo de tipos puede expandirse de manera más eficiente y correcta [...]. En segundo lugar, contar con constructores de encapsulamiento y abstracción le brinda al lenguaje la posibilidad de definir nuevos tipos de datos abstractos."*
> — 05-Tipos.pdf (p. 1)

**Ejemplo con tipos distintos (Ada o Haskell):**
```haskell
newtype Temperatura = Temperatura Double
newtype Peso        = Peso Double

-- Esto ahora es un ERROR DEL LENGUAJE (detectable):
suma :: Temperatura -> Peso -> ?   -- error: tipos incompatibles
```

Al definir `Temperatura` y `Peso` como tipos distintos, el lenguaje puede detectar la mezcla incorrecta, convirtiendo lo que era un error de aplicación en un error del lenguaje.

---

### Resumen comparativo

| | Error del lenguaje | Error de aplicación |
|---|---|---|
| **Definición** | Viola una regla del sistema de tipos | Incorrecto en el dominio del problema, pero legalmente tipado |
| **Detección** | El lenguaje puede (y debe) detectarlo | El lenguaje no puede detectarlo |
| **Relación con tipado fuerte** | Un lenguaje fuertemente tipado detecta *todos* estos errores | Fuera del alcance de la propiedad; responsabilidad del programador |
| **Ejemplo** | `"hola" + 5` en Python | Sumar temperatura y peso representados como `float` |
