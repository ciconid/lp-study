## Codigo del enunciado
```JavaScript
function generar() {
    var contador = 0;
    function sumar() {
        contador++;
        console.log(contador);
    }
    return sumar;
}

var contar1 = generar();
var contar2 = generar();
contar1();
contar1();
contar2();
contar1();
```

### ¿Qué es un closure?

Un closure es una función que **captura y mantiene vivo el entorno léxico** en el que fue creada, incluso después de que ese entorno haya dejado de estar en ejecución.

La definición clave no es "función dentro de otra función" --- eso es solo la sintaxis. Lo que define un closure es que la función interna **retiene acceso a las variables de su scope externo más allá del tiempo de vida de ese scope**.

* * * * *

### Por qué no es simplemente "función dentro de otra función"

Para entenderlo hay que analizar los **atributos de las variables** involucradas.

En la mayoría de los lenguajes, una variable local tiene tres atributos relevantes:

-   **Alcance (scope):** dónde en el código es visible el nombre.
-   **Tiempo de vida (lifetime):** cuánto tiempo existe la celda de memoria.
-   **Valor:** el contenido almacenado.

En el modelo tradicional (sin closures), cuando una función termina su ejecución, sus variables locales **mueren** --- el stack frame se destruye y la memoria se libera. El alcance y el tiempo de vida están sincronizados.

Lo que hace un closure es **desacoplar el alcance del tiempo de vida**:

javascript

```
function generar() {
  var contador = 0;   // variable local de generar()
  function sumar() {
    contador++;       // sumar() referencia a contador
    console.log(contador);
  }
  return sumar;       // generar() termina... pero contador NO muere
}

var contar1 = generar(); // generar() ya terminó
contar1();               // pero contador sigue vivo: imprime 1
```

Cuando `generar()` retorna, su stack frame debería destruirse. Sin embargo, como `sumar` fue retornada y sigue viva (referenciada por `contar1`), el motor de JavaScript detecta que `contador` es necesaria y la **mueve al heap**, manteniéndola viva mientras el closure exista.

-   El **alcance** de `contador` sigue siendo solo el interior de `generar()` --- ningún código externo puede nombrarla directamente.
-   El **tiempo de vida** de `contador` se extiende indefinidamente, atado a la vida del closure.

* * * * *

### Por qué `contar1` y `contar2` son independientes

Cada llamada a `generar()` crea un **nuevo entorno léxico** con su propio `contador`. `contar1` y `contar2` son dos closures distintos, cada uno con su propia celda de memoria para `contador`. No comparten estado.

* * * * *

### Resumen

Un closure no es solo sintaxis de anidamiento. Es un mecanismo que altera el atributo **tiempo de vida** de las variables locales capturadas, extendiéndolo más allá del retorno de la función que las declaró, mientras preserva su **alcance** restringido. Esa combinación --- larga vida, alcance acotado --- es lo que lo hace útil para encapsular estado privado.
