# Evaluación de expresiones en JavaScript

Al evaluar las expresiones proporcionadas en JavaScript, se obtienen los siguientes resultados basados en el sistema de coerciones (conversiones implícitas) y el manejo de tipos del lenguaje.

## 1. Expresión: `"hola" * 4`

### Resultado

```javascript
NaN
```

(*Not a Number*)

### ¿Por qué?

En JavaScript, cuando se utilizan los operadores aritméticos `*`, `/`, `-` o `%` entre un `string` y un número, el lenguaje intenta realizar una coerción del `string` a número para poder operar.

Debido a que la cadena `"hola"` no tiene un formato numérico válido, el motor de ejecución la convierte al valor especial `NaN`.

Cualquier operación aritmética realizada con `NaN` da como resultado `NaN`.

---

## 2. Expresión: `"hola".longitud < 3`

### Resultado

```javascript
false
```

### ¿Por qué?

Esta expresión involucra dos pasos semánticos.

#### Acceso a propiedad inexistente

Los objetos de cadena en JavaScript tienen la propiedad estándar `.length` para medir su tamaño.

Al intentar acceder a una propiedad que no existe, como `.longitud`, JavaScript no lanza un error, sino que devuelve el valor `undefined`.

Por lo tanto:

```javascript
"hola".longitud
```

se evalúa como:

```javascript
undefined
```

#### Comparación relacional

La expresión se reduce a:

```javascript
undefined < 3
```

En los contextos de comparación relacional con números, JavaScript intenta convertir los operandos a valores numéricos.

El valor `undefined` convertido a número es:

```javascript
NaN
```

Por regla general en el lenguaje, cualquier comparación relacional (`<`, `>`, `<=`, `>=`) que involucre a `NaN` devuelve `false`.

---

## Conclusión sobre el diseño

Estos comportamientos son consecuencia de que JavaScript sea un lenguaje de **tipado dinámico** con un sistema de **coerciones agresivo**.

El objetivo de este diseño es evitar que el programa se detenga por errores de tipos, forzando a los operandos a "mutar" hacia el tipo que el contexto de la operación requiere, aunque esto pueda derivar en resultados semánticamente confusos.
