# ¿Es Java un lenguaje fuertemente tipado?

Según la definición de la cátedra, un lenguaje es **fuertemente tipado** (*strongly typed*) si garantiza la detección de todos los errores de tipos, ya sea en tiempo de compilación o de ejecución.

Bajo este criterio estricto, **Java no es considerado un lenguaje fuertemente tipado** (se lo define como *"casi" fuertemente tipado*) debido principalmente a la presencia de **coerciones** y **expresiones mixtas**.

## Razones por las que Java no cumple la propiedad

### Debilitamiento por coerciones

Las fuentes indican que la propiedad de tipado fuerte se pierde si existe aunque sea un solo detalle que el sistema no sea capaz de detectar como error.

En Java, las coerciones (conversiones implícitas de tipo) permiten que el lenguaje "arregle" automáticamente una discrepancia de tipos en lugar de informar un fallo al programador.

### Expresiones mixtas

Al permitir operadores que aceptan operandos de diferentes tipos (como sumar un entero y un real), Java prioriza la flexibilidad por sobre la detección de errores.

Esto puede ocultar potenciales equivocaciones lógicas o errores de escritura.

### Inseguridad en tiempo de diseño

Aunque el diseño de Java requiere chequeos en casi todas las variables y expresiones, lo que elimina virtualmente los errores de tipos en tiempo de ejecución, la existencia de reglas de conversión implícita debilita la fiabilidad del sistema de tipos comparado con lenguajes más estrictos como ML o Haskell.

## Ejemplo ilustrativo

Consideremos el siguiente código:

```java
int a, b;
float d;

// ... asignaciones ...

float resultado = a + d;
```

Supongamos que el programador tenía la intención de escribir:

```java
float resultado = a + b;
```

pero, por un error de escritura (*typo*), utilizó la variable `d` en lugar de `b`.

### Análisis del comportamiento

#### En un lenguaje fuertemente tipado puro

El sistema detectaría que se intenta sumar un `int` con un `float` y lanzaría un error de tipos, obligando al programador a corregir el nombre de la variable o a realizar una conversión explícita.

#### En Java

El compilador no detecta el error.

En su lugar, aplica una coerción implícita, convirtiendo automáticamente el valor de `a` a `float` para realizar una suma de punto flotante.

Conceptualmente, la operación se transforma en algo equivalente a:

```java
float resultado = (float) a + d;
```

## Conclusión

Este comportamiento demuestra que Java no garantiza la detección de todos los errores de tipos, ya que el sistema asume que la mezcla de tipos fue intencional y permite la operación mediante conversiones implícitas.

Por esta razón, bajo la definición estricta utilizada por la cátedra, Java se considera un lenguaje **casi fuertemente tipado**, pero no **fuertemente tipado** en sentido estricto.
